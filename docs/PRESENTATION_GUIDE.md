# IT ACADEMY 프로젝트 발표 및 시연 가이드

## 1. 핵심 소개 문장

IT ACADEMY는 AI·데이터·소프트웨어 교육을 소개하는 웹 서비스입니다. 교육과정 홍보에 머무르지 않고 교육 철학, 학습 단계, 프로젝트 산출물, 심사 기준, 상담과 관리자 운영 기능을 하나의 사용자 흐름으로 연결했습니다.

## 2. 발표 흐름

| 순서 | 화면 | 설명 포인트 |
|---|---|---|
| 1 | 메인 | 타이포그래피 중심 히어로와 학습 표준 패널로 이해·구현·검증의 학습 흐름을 소개합니다. |
| 2 | 교육 철학 | 문제 정의부터 구현·검증·발표까지 이어지는 교육 루프를 설명합니다. |
| 3 | 교육과정 | 과정별 목표·기술·커리큘럼·프로젝트·학습 산출물을 보여줍니다. |
| 4 | 프로젝트 갤러리 | 프로젝트의 문제·접근·산출물·평가 포인트를 비교합니다. |
| 5 | 심사 기준 | 100점 평가 구조로 화면이 아니라 개발 과정과 품질 증거를 평가하는 방향을 제시합니다. |
| 6 | 상담 | 실제 서버 연동 환경에서 검증·개인정보 동의·중복 접수 방지를 시연합니다. |
| 7 | 관리자 | 과정·공지·상담 관리와 관리자 권한 분리를 설명합니다. |
| 8 | 코드·테스트 | React JS 구조, Spring 계층, REST API, 자동화 테스트를 제시합니다. |

## 3. 권장 시연 순서

### 공개 화면

1. 메인 히어로의 핵심 메시지와 이해·구현·검증 단계, 교육 설계 섹션을 보여줍니다.
2. 교육 철학에서 5단계 학습 루프를 설명합니다.
3. 교육과정 목록에서 분야별 과정과 상세 커리큘럼을 확인합니다.
4. 프로젝트 갤러리에서 카테고리를 바꾸고 상세 모달을 엽니다.
5. 프로젝트 섹션에서 요구사항·설계·구현·테스트·배포·회고로 이어지는 포트폴리오 증거 구조를 설명합니다.
6. 평가 프레임워크에서 100점 배점과 테스트·문서 기준을 설명합니다.
7. 교육과정 목록의 네 가지 분야별 학습 경로와 대표 산출물을 비교합니다.
8. 상담 페이지에서 사전 준비 항목과 필수·선택 입력 정보를 확인합니다.

### 상담·관리자

1. 백엔드와 MySQL이 실행된 환경에서 상담 신청을 제출합니다.
2. 필수 동의 누락 요청을 서버가 거절하는지 확인합니다.
3. 동일 연락처의 중복 접수가 차단되는지 확인합니다.
4. 관리자 계정으로 로그인합니다.
5. 교육과정을 수정하고 공개 화면에서 내용이 반영되는지 확인합니다.
6. 공지사항을 게시·비공개 전환합니다.
7. 상담 신청 상태와 내부 메모를 변경합니다.
8. 일반 관리자에게 최고 관리자 기능이 노출되지 않는지 확인합니다.

## 4. 심사자가 확인해야 할 구현 근거

- 프론트엔드: frontend/src/App.js, frontend/src/academy-pages.js, frontend/src/academy.css
- 공통 API 및 CSRF: frontend/src/api.js
- 백엔드 공개 API: PublicController.java
- 프로젝트 카탈로그: ProjectCatalogService.java
- 상담 검증: InquiryController.java, InquiryService.java
- DB 검색 및 페이지 처리: InquiryRepository.java, AdminInquiryController.java
- 보안: SecurityConfig.java
- 자동화 테스트: AdminApiIntegrationTest.java
- 자동화 빌드: .github/workflows/build.yml

## 5. 시연 시 유의사항

GitHub Pages 정적 미리보기는 화면 확인용입니다. 백엔드가 연결되지 않으므로 상담 접수나 관리자 DB 변경이 실제로 저장되지 않습니다. 실제 저장 동작은 로컬 또는 서버의 풀스택 실행 환경에서 시연해야 합니다.

프로젝트 사례는 교육 설계 예시입니다. 실제 수강생의 작품이나 수상·취업 실적이라고 소개해서는 안 됩니다.

공식 운영 일정·교육비·정원·기관 연락처·강사 이력은 확인된 자료를 준비한 뒤 공개해야 합니다.
