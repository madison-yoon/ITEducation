# 시스템 구조·품질·테스트 기준

## 1. 프로젝트 범위

IT ACADEMY는 교육과정과 프로젝트 학습 방식을 안내하는 웹 서비스입니다.

### 포함 범위

- 반응형 공개 웹사이트
- 교육 철학·교육과정·프로젝트·공지·상담 정보 흐름
- 프로젝트 교육 사례 카탈로그 API
- 상담 신청 및 관리
- 교육과정·공지 관리
- 세션 기반 관리자 로그인과 역할 관리
- Docker Compose 배포 구성
- GitHub Actions 기반 빌드 검사

### 범위 밖 또는 추가 운영 준비가 필요한 항목

- 실제 교육기관의 사업자·인가·시설 정보
- 실제 강사 이력, 수강생 작품, 취업 통계, 수상 실적
- 실제 모집 일정, 교육비, 장학·지원 제도
- 상담 신청 이메일·문자 발송 연동
- 개인정보 처리방침·보유 기간·삭제 정책의 법무 검토
- 운영 서버 백업·모니터링·로그 보관 정책
- 외부 AI API 키 관리 및 과금 정책

확인되지 않은 운영 정보는 임의로 생성하지 않습니다.

## 2. 기술 아키텍처

| 계층 | 구현 역할 |
|---|---|
| React 화면 | 사용자 흐름, 접근성, 반응형 UI |
| Axios API 모듈 | 공통 API 주소, 세션 쿠키, CSRF 토큰 |
| Controller | HTTP 라우팅과 요청 검증 |
| Service | 상담 동의, 연락처 정규화, 중복 접수 규칙 |
| Repository | 엔티티 조회와 DB 페이징 검색 |
| Entity | 과정·공지·상담·관리자 데이터 |
| MySQL | 영속 데이터 저장 |

프론트엔드는 JavaScript .js 파일만 사용하고 JSX를 도입하지 않습니다. 공개 페이지의 상세 화면은 별도 모듈로 분리했습니다.

## 3. 교육과정 운영정보 공개 원칙

교육과정에는 운영정보 확인 여부를 저장합니다. 관리자가 확인 완료를 표시하기 전에는 공개 API에서 모집 상태, 교육 기간, 지원 대상을 중립적인 확인 필요 문구로 반환합니다. 이 규칙은 기존 DB에 저장된 초기 예시 데이터에도 적용됩니다. 확인된 운영 정보만 실제 상태로 공개합니다.

## 4. 공개 프로젝트 API 계약

GET /api/projects 응답은 각 프로젝트의 목적과 심사 항목을 화면과 같은 구조로 제공합니다.

주요 필드:

- id, title, category
- duration, teamSize
- description, problem, solution
- features, stack
- result, deliverables, evaluationPoints
- disclosure

disclosure 값은 교육 설계 예시임을 표시합니다. 프론트엔드는 API 응답이 없을 때 같은 구조의 제한된 예시 데이터로 화면을 확인할 수 있습니다.

## 5. 상담 API 검증

POST /api/inquiries는 아래 조건을 서버에서 검증합니다.

| 필드 | 규칙 |
|---|---|
| 이름 | 필수, 최대 40자 |
| 연락처 | 필수, 허용 문자와 길이 검증 |
| 이메일 | 선택, 입력 시 이메일 형식, 최대 120자 |
| 교육과정명 | 필수, 최대 120자 |
| 상담 희망 시간대 | 최대 40자 |
| 상담 내용 | 필수, 10~2,000자 |
| 개인정보 동의 | 필수 |
| 마케팅 동의 | 선택 |

연락처는 숫자만 추출한 값으로 정규화합니다. 동일 연락처에 진행 중인 신청이 있는 경우 중복 접수를 차단합니다.

상담 API는 CSRF 보호 대상입니다. 클라이언트가 제출 버튼을 비활성화하더라도 서버가 동의 여부를 다시 검사합니다.

## 6. 오류 응답

공통 예외 처리기는 검증 오류와 잘못된 요청 형식, 찾을 수 없는 리소스, 권한 오류, 예상하지 못한 서버 오류를 일관된 JSON 구조로 반환합니다.

응답 필드:

- timestamp
- status
- error
- message
- fieldErrors

내부 예외 메시지와 스택 정보는 클라이언트 응답에 포함하지 않습니다. 예상하지 못한 오류는 서버 로그에 기록합니다.

## 7. 관리자 보안

- 비밀번호는 BCrypt로 저장합니다.
- 관리자 회원가입은 공개하지 않습니다.
- 최초 최고 관리자 계정은 환경 변수를 통해 생성합니다.
- 관리자 API는 세션 인증을 요구합니다.
- 상태 변경 요청에는 CSRF 토큰을 적용합니다.
- 최고 관리자 계정 관리는 별도 권한으로 제한합니다.
- 세션 쿠키는 HttpOnly 및 SameSite 설정을 사용합니다.

운영 배포에서는 HTTPS, 강한 DB 비밀번호, 비밀키 환경 변수, 접근 로그, 백업·복구 정책을 추가로 검증해야 합니다.

## 8. 관리자 상담 검색

상담 신청의 검색·상태 필터·페이지 나누기는 DB 쿼리에서 처리합니다. 전체 데이터를 서버 메모리로 가져와 검색하는 방식은 사용하지 않습니다. 페이지 크기는 1~50 범위로 제한합니다.

## 9. 자동화 테스트

GitHub Actions의 Build Check는 다음 항목을 확인합니다.

| 작업 | 검증 내용 |
|---|---|
| Frontend | npm 의존성 설치, Vite 프로덕션 빌드 |
| Backend | Gradle clean build, JUnit 테스트 |
| Deployment | Docker Compose 구성 검증, 이미지 빌드 |

통합 테스트 대상:

- 공개 교육과정 API 접근
- 관리자 비로그인 접근 차단
- 일반 관리자와 최고 관리자 권한 차이
- CSRF 없는 상태 변경 요청 거부
- 권한 있는 과정 생성
- 공지 게시 후 공개 API 조회
- 운영정보 확인 상태에 따른 교육과정 공개 데이터 제한
- 프로젝트 API 상세 응답 계약
- 상담 화면의 필수·선택 입력 정보 안내
- 교육과정 분야별 학습 경로와 산출물 안내
- 프로젝트 이미지 자산 및 콘텐츠 연결
- 홈페이지 포트폴리오 증거 구조
- 상담 입력값 검증 및 필드 오류
- 필수 개인정보 동의
- 동일 연락처 중복 상담 방지

자동화 CI는 로컬 실제 브라우저, 운영 DB, 실제 이메일 발송, 운영 HTTPS 설정을 대체하지 않습니다.

## 10. 수동 QA 체크리스트

### 공개 화면

- [ ] 데스크톱·태블릿·모바일에서 레이아웃이 깨지지 않는지 확인
- [ ] 모바일 내비게이션 열기·닫기 및 메뉴 이동 확인
- [ ] 교육과정 검색과 분야 필터 확인
- [ ] 관리자에서 새로 등록한 과정의 상세 콘텐츠 확인
- [ ] 프로젝트 카테고리 필터와 상세 모달 확인
- [ ] 모달 ESC·닫기 버튼·배경 클릭 동작 확인
- [ ] 공지 검색·분류·상세 링크 확인
- [ ] API 실패 시 가짜 운영 정보 대신 오류 안내 확인
- [ ] 정적 미리보기에서 상담 미접수 안내 확인

### 상담

- [ ] 필수 입력 누락 시 브라우저 안내 확인
- [ ] 유효하지 않은 이메일·연락처 입력 확인
- [ ] 개인정보 동의 없이 API 요청 시 서버가 거절하는지 확인
- [ ] 정상 신청 후 접수 번호 확인
- [ ] 동일 연락처 중복 신청이 차단되는지 확인

### 관리자

- [ ] 비로그인 상태에서 관리자 API 접근이 차단되는지 확인
- [ ] 일반 관리자와 최고 관리자 권한 차이 확인
- [ ] 과정 생성·수정·삭제 후 공개 화면 반영 확인
- [ ] 공지 게시·비공개 전환 후 공개 목록 반영 확인
- [ ] 상담 검색·페이지 이동·상태 변경·내부 메모 확인
- [ ] 관리자 계정 변경 권한 확인
