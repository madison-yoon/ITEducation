# IT ACADEMY — 전체 사이트 UX·코드 품질 감사

**감사 기준일:** 2026-11-10  
**대상:** `main` 기준 저장소와 `quality/full-site-audit-and-ux` 개선 브랜치  
**목표:** 홍보용 화면에서 실제 운영 준비가 가능한 교육기관 웹 제품으로 발전시키기 위한 UX·기능·접근성·보안·배포 감사

## 1. 요약

기존 사이트는 어두운 그라데이션, 3D CSS 그래픽, 과정 및 프로젝트 카드 등 시각적 요소는 갖추고 있었습니다. 다만 정보 구조와 인터랙션의 세부 완성도는 화면 효과에 비해 약했습니다.

가장 명확한 사용자 경험 결함은 경로 이동 후 스크롤 위치가 이전 페이지의 중간 위치에 남는 문제였습니다. 그 외에도 페이지별 문서 제목 부재, 알 수 없는 경로의 전용 404 화면 부재, 프로젝트 상세 모달의 포커스 제어 미흡, 화면 이탈 후 진행 중인 API 요청 처리, 과정 검색 범위, 작은 보조 글자, 관리자 API의 과도한 데이터 반환을 확인했습니다.

## 3. 주요 발견 사항과 개선

| 영역 | 확인한 문제 | 개선 |
|---|---|---|
| 라우팅 | 페이지 이동 시 이전 스크롤 위치가 남을 수 있음 | PUSH·REPLACE 시 최상단 이동, 브라우저 POP 시 이전 위치 복원 |
| 페이지 접근성 | 경로별 문서 제목과 페이지 안내가 없음 | 페이지별 document.title·meta description·aria-live 안내 |
| 경로 오류 | 미등록 URL의 전용 화면 부재 | 404 전용 화면 및 과정·공지 이동 링크 |
| 모바일 메뉴 | Escape 처리와 경로 변경 시 닫힘 정책 미흡 | 경로 변경·Escape 시 닫힘, aria-controls 연결 |
| 프로젝트 상세 | 모달이 배경 스크롤과 키보드 포커스를 완전히 관리하지 않음 | 배경 스크롤 잠금, Tab 포커스 트랩, Escape 닫기, 트리거 포커스 복원 |
| 비동기 요청 | 화면 이탈 후 오래된 응답이 상태를 덮을 수 있음 | 과정·공지·프로젝트 요청에 AbortController 적용 |
| 과정 탐색 | 과정명 중심의 제한된 검색 | 분야·소개·기술 키워드 검색, 결과 수, 로딩·빈 결과 상태 |
| 상담 입력 | 입력 목적에 맞는 자동완성·전화 키패드·날짜 제한이 부족 | autocomplete·inputMode·날짜 min·서버 날짜 검증·오류 안내 개선 |
| API 안정성 | 요청 타임아웃이 없어 응답 대기 상태가 길어질 수 있음 | Axios 요청 타임아웃과 CSRF URL 처리 보강 |
| 관리자 데이터 | 상담 엔티티 전체가 API에 반환되어 내부 판정·동의 필드까지 노출 | 화면에 필요한 필드만 반환하는 AdminInquiryResponse DTO |
| 컨테이너 빌드 | Docker 프론트엔드 빌드가 npm install 사용 | package-lock.json을 따르는 npm ci |
| 저장소 관리 | Gradle 캐시가 Git에 추적됨 | 실행 캐시 파일 제거, 기존 .gitignore 규칙 유지 |
| SEO·브랜드 | 파비콘과 크롤러 안내 자산 부족 | SVG favicon, robots.txt, sitemap.xml 추가 |
| 테스트 | 스크롤 정책과 경로 메타데이터의 단위 테스트가 없음 | Node 내장 test로 PUSH/REPLACE/POP과 경로 메타데이터 검증 |

## 4. 구현한 화면 동작 기준

새로운 경로로 이동하면 페이지 최상단에서 시작합니다. 브라우저 뒤로 가기와 앞으로 가기는 저장된 스크롤 위치를 복원합니다. 해시 링크는 대상 요소로 이동합니다.

페이지마다 고유 문서 제목과 설명을 설정합니다. 경로가 바뀌면 스크린 리더용 라이브 영역이 현재 페이지를 알립니다. 새 페이지의 main 영역에 포커스를 이동해 키보드 탐색 흐름을 유지합니다.

프로젝트 상세 모달은 열려 있는 동안 배경 스크롤을 잠급니다. Tab과 Shift+Tab은 모달 안에서 순환합니다. Escape로 닫을 수 있습니다. 닫은 후에는 모달을 열었던 카드로 포커스를 돌려줍니다.

과정 검색은 과정명·분야·소개·기술 정보를 대상으로 합니다. 검색 조건에 맞는 과정이 없을 때 원인을 알려주고 필터를 초기화할 수 있습니다.

상담 희망 날짜는 오늘 이전으로 선택할 수 없습니다. 브라우저 검증을 우회한 요청도 서버에서 다시 검사합니다.

## 5. 개인정보·보안 검토

상담 신청에는 이름·연락처·이메일·관심 과정·상담 내용이 포함됩니다. 관리자 목록과 대시보드에서 화면에 필요하지 않은 정규화 연락처 및 개인정보 동의 원본은 반환하지 않도록 DTO를 분리했습니다.

현재 코드에는 세션 인증, BCrypt 비밀번호 해시, CSRF 검증, 관리자 역할 구분이 있습니다. 상담 중복 신청 검증과 서버 입력값 검증도 유지합니다.

다음 항목은 실제 운영 전 기관의 정책과 인프라 정보가 필요합니다.

- 개인정보 수집·이용 목적, 보관 기간, 파기 기준, 처리 담당자, 문의 연락처가 포함된 확정 개인정보 처리 안내
- 개인정보 처리 동의 버전과 동의 시점의 기록 정책
- 공개 상담 API의 스팸·봇 방지와 요청 빈도 제한
- 데이터베이스 백업·복구 주기와 접근 기록 보관
- 운영 스키마 변경 이력 관리와 마이그레이션 도입
- 실제 도메인·서버·모니터링·장애 대응 담당자

이 정보는 저장소에 제공되지 않았으므로 임의로 채우지 않았습니다.

## 6. 운영 배포 경계

GitHub Pages는 프론트엔드 정적 미리보기입니다. 백엔드 API와 MySQL을 실행하지 않습니다. 따라서 GitHub Pages에서 상담 양식의 실제 접수나 관리자 데이터 변경이 저장된다고 표시해서는 안 됩니다.

실제 운영에는 별도 서버, 도메인, HTTPS, 환경 변수, MySQL 백업과 복구 절차가 필요합니다. 현재 Docker Compose와 Caddy·Nginx·Spring Boot 구성이 전체 서비스 배포의 기반입니다.

## 7. 검증 계획

- 프론트엔드: `npm ci`, `npm test`, `npm run build`
- 백엔드: `gradle clean test build`
- 배포 구성: `docker compose config --quiet`, Docker 이미지 빌드
- Pages: 정적 파일 빌드, 404 fallback, artifact 업로드, 배포 job
- 브라우저 자동화: Chromium에서 메인·과정·공지 이동, 프로젝트 이미지 로딩, 프로젝트 모달 Escape·포커스 복원, 정적 예시 공지 구분, 상담 정적 미리보기 차단, 404, 360px 가로 넘침 등 10개 회귀 시나리오
- 브라우저 수동 확인: 실제 배포 URL에서 데스크톱·모바일, 뒤로·앞으로, 해시 링크, 390px·768px·1024px·1440px 레이아웃과 키보드 탐색

자동화된 Chromium 검증은 2026-11-10 기준 통과했습니다. 자동화 테스트는 실기기별 시각 검수를 대체하지 않으므로 나머지 해상도와 실제 배포 URL 확인은 별도 체크리스트로 유지합니다.

## 8. 향후 우선순위

1. 실제 기관 콘텐츠: 운영 일정·비용·정원·강사진·연락처·위치·개인정보 처리 안내를 기관 승인 자료로 입력합니다.
2. 운영 백엔드: 서버·DB·도메인·백업·스팸 방지를 구성합니다.
3. 디자인 시스템 정리: 기존 styles.css·academy.css·professional.css에 누적된 중복 선택자와 override 층을 컴포넌트 단위로 통합합니다.
4. 실제 브라우저 QA: 360px·390px·768px·1024px·1440px 화면과 키보드 탐색을 검증합니다.
5. 콘텐츠 증거: 실제 작품·수강생 성과가 확보된 경우에만 출처·기간·측정 기준과 함께 공개합니다.
