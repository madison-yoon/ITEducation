# 교육 설계와 AI 협업 원칙

## 1. 교육 설계 방향

이 프로젝트가 제안하는 교육의 핵심은 도구의 사용법보다 문제 해결의 전체 흐름을 학습하는 것입니다. 학습자는 결과물을 만드는 과정에서 기술 선택의 이유와 검증 방법을 설명할 수 있어야 합니다.

### 학습 루프

| 단계 | 학습 활동 | 확인할 산출물 |
|---|---|---|
| 문제 정의 | 사용자와 문제, 요구사항, 완료 조건을 구체화 | 요구사항 명세, 사용자 흐름 |
| 기초 원리 | 개념과 도구의 역할을 이해하고 작은 과제로 확인 | 개념 노트, 기초 실습 |
| AI 협업 | AI 결과를 읽고 수정하며 생성 근거와 변경 내용을 기록 | 프롬프트 기록, 변경 이력 |
| 제품 구현 | 프론트엔드·백엔드·데이터를 연결 | 화면, API, DB, 통합 기능 |
| 검증·발표 | 정상·오류·경계 조건을 테스트하고 결과를 설명 | 테스트 결과, README, 시연, 회고 |

각 단계는 이전 단계의 산출물을 다음 단계의 입력으로 사용합니다. 기능만 급하게 구현하고 요구사항이나 데이터 구조를 생략하지 않도록 설계했습니다.

## 2. Vibe Coding을 교육에 적용하는 원칙

AI 코딩 도구는 생산성을 높이는 수단이지만, 생성된 코드가 정확하거나 안전하다는 보증은 아닙니다. 따라서 AI가 만든 코드도 일반적인 코드 리뷰와 테스트 절차를 통과해야 합니다.

### AI 협업 작업 절차

1. 요구사항을 기능 단위로 나누고 완료 조건을 정합니다.
2. AI에게 역할·맥락·제약·입력·출력 형식을 구체적으로 전달합니다.
3. 생성된 코드의 파일 구조와 데이터 흐름을 읽습니다.
4. 필요한 부분을 직접 수정하고 불필요한 의존성을 제거합니다.
5. 정상 입력·잘못된 입력·경계 조건을 테스트합니다.
6. 보안·개인정보·라이선스·접근성 위험을 점검합니다.
7. 사용 프롬프트, 수정 이유, 테스트 증거를 작업 기록에 남깁니다.
8. 제출자는 주요 로직과 선택한 기술을 자신의 언어로 설명합니다.

### AI 생성 코드 검토 체크리스트

- 요구사항과 실제 구현이 일치하는가.
- 생성 코드가 기존 구조와 의존성을 불필요하게 늘리지 않는가.
- 입력값 검증과 오류 처리가 있는가.
- 인증·권한·개인정보·비밀키 노출 위험이 없는가.
- 외부 라이브러리와 생성 이미지·텍스트의 라이선스를 확인했는가.
- 핵심 기능을 재현할 테스트가 있는가.
- 작성자가 주요 코드 흐름을 직접 설명할 수 있는가.

## 3. 프로젝트 유형별 학습 결과

| 분야 | 프로젝트 예시 | 주요 학습 역량 | 제출 산출물 |
|---|---|---|---|
| AI·웹 | AI 영화 추천 플랫폼 | 데이터 정제, 추천 로직, API 통합 | 데이터 사전, 모델, 평가 보고서, API 명세 |
| 데이터 분석 | 소비 데이터 인사이트 랩 | SQL, 전처리, 지표 설계, 시각화 | 품질 보고서, SQL, 대시보드, 분석서 |
| 생성형 AI | 근거 중심 문서 AI | 문서 파싱, 임베딩, 검색, RAG 평가 | 구성도, 평가 데이터셋, API 문서 |
| NLP | VOC 분류·분석 | 라벨링, 분류 모델, 클래스 불균형, 오분류 분석 | 라벨 가이드, 혼동 행렬, 모델 카드 |
| 웹 개발 | 학습 운영 플랫폼 | 권한, DB 모델링, REST API, 통합 테스트 | 요구사항, ERD, API 명세, 테스트 케이스 |
| AI 협업 개발 | Vibe Coding 품질 검증 워크벤치 | 요구사항 추적, AI 사용 기록, 리뷰, 테스트 | 작업 분해표, AI 사용 로그, 리뷰, 테스트 리포트 |

위 프로젝트는 교육 설계를 설명하는 예시입니다. 실제 수강생 작품이나 운영 실적을 의미하지 않습니다.

## 5. 학습 성과의 증거

프로젝트가 완성됐다는 주장은 실행 가능한 코드만으로 충분하지 않습니다. 최소한 아래 자료가 함께 있어야 평가자가 결과를 검증할 수 있습니다.

- 요구사항 명세와 완료 조건
- 주요 화면 및 사용자 흐름
- API 명세와 데이터 모델
- 핵심 코드와 기술 선택 이유
- 정상·오류·경계 테스트 결과
- 코드 리뷰 및 수정 이력
- 설치·실행·배포 안내
- 발표 자료와 회고

## 6. 교육 콘텐츠 운영 시 주의사항

실제 운영 전에는 과정별 교육 시간, 주차별 세부 시수, 강사·멘토 구성, 선수 지식, 과제량, 장비·라이선스, 교육비, 모집 일정, 정원, 환불·지원 제도를 확정해야 합니다. 이 저장소에는 확인되지 않은 기관 운영 정보를 사실처럼 게시하지 않습니다.
