# IT ACADEMY 최종 품질 감사 및 제출 점검

**기준일:** 2026-11-10  
**대상:** `main` 이후 사이트 완성 보완 브랜치  
**범위:** 전체 공개 페이지, 교육과정·프로젝트 콘텐츠, 이미지, 한국어 타이포그래피, 반응형·접근성, 상담·공지의 운영 경계, 관리자 기능, 자동화 검증

## 1. 최종 점검 원칙

사이트는 교육기관의 실제 운영 사실을 확인할 수 있는 자료와 교육 설계를 설명하기 위한 예시를 구분해야 합니다. 실제 주소·연락처·강사 이력·모집 일정·교육비·정원·취업률·수강생 작품을 확인하지 못한 경우 임의로 만들지 않습니다.

브랜드 경험은 화면 효과보다 정보 이해와 다음 행동을 우선합니다. 메인부터 과정·프로젝트·공지·상담까지 같은 타이포그래피, 색상 토큰, 간격, 입력·버튼·포커스 규칙을 사용합니다.

## 3. 콘텐츠 구조와 공개 기준

### 교육과정

네 가지 과정은 AI·머신러닝, 빅데이터 분석, 생성형 AI 서비스, 풀스택 웹 서비스로 나뉩니다. 과정명과 학습 설명은 홈과 과정 목록에서 하나의 카탈로그 데이터를 사용합니다. 개강일·교육 기간·정원·교육비·지원 자격은 운영기관이 확인한 정보만 표시합니다.

각 상세 페이지는 학습 목표, 단계별 커리큘럼, 실습·산출물·완료 기준, 최종 프로젝트, 평가 원칙, FAQ를 연결합니다. 실제 강의 운영이 확인되지 않은 혜택이나 취업 성과는 확정 표현으로 제시하지 않습니다.

### 프로젝트 사례와 이미지

프로젝트 여섯 개는 교육 설계를 설명하기 위한 가상 예시입니다. 실제 수강생 결과물이나 기관의 실적이 아닙니다. 각 SVG는 같은 편집 디자인 팔레트와 화면 비율을 사용하고, 홈·갤러리·상세 모달에서 같은 프로젝트에 연결합니다.

프로젝트 상세에는 다음 근거를 포함합니다.

- 해결할 문제와 설계 접근
- 기능 범위와 기술 구성
- 데이터·화면·API 아키텍처
- 5단계 구현 흐름
- 재현 가능한 완료 기준
- 개인정보·보안·데이터 품질·모델 평가 등 분야별 통제 사항

### 공지사항과 정적 미리보기

GitHub Pages는 백엔드가 연결되지 않은 정적 미리보기입니다. 이 환경에서 제공되는 공지 10개는 시연용 예시이며 실제 운영 공지로 오인되지 않도록 목록과 상세에 구분 문구를 표시합니다. 실제 서버의 공지에는 정적 미리보기 문구를 붙이지 않습니다.

상담 신청도 백엔드가 없을 때 접수 완료를 표시하거나 데이터를 저장한 것처럼 처리하지 않습니다.

## 5. 자동화 검증

GitHub Actions Build Check는 다음을 실행합니다.

- 프론트엔드 프로덕션 빌드와 Node 내장 테스트
- Chromium 기반 Playwright 10개 시나리오
- Spring Boot 백엔드 테스트 및 빌드
- Docker Compose 구성 검증과 프론트엔드·백엔드 이미지 빌드

브라우저 시나리오는 홈·과정 이동, Pretendard 로딩, 전체 공개 경로의 디자인 토큰, 시연용 공지 표기, 갤러리와 홈 프로젝트 이미지, 프로젝트 상세 모달, Escape·포커스 복원, 백엔드 없는 상담 접수 차단, 404 화면, 360px 가로 넘침을 검사합니다.

이전 main CI에서 홈의 지연 로딩 이미지 테스트가 Playwright의 `scrollIntoViewIfNeeded` 호출 중 제한 시간을 초과했습니다. 이미지 경로 오류가 아니라 테스트가 부드러운 스크롤 완료를 기다리며 멈춘 것이 Trace에서 확인되어, 테스트 대상 이미지의 lazy 상태를 eager로 전환하고 실제 이미지의 `naturalWidth`를 확인하는 방식으로 바꿨습니다. 사용자 화면의 지연 로딩 동작은 유지합니다.

## 6. 실제 운영 전 외부 확정 사항

다음 정보는 코드만으로 사실 여부를 결정할 수 없으므로 기관 담당자의 확인이 필요합니다.

- 공식 기관명·사업자·주소·대표 연락처·운영 주체
- 교육과정별 실제 개강일·수업 시간·교육 기간·정원·비용·지원 자격
- 강사·멘토 이력과 실제 수강생 작품·수료·취업 실적
- 개인정보 처리 주체·보유 기간·파기 절차·문의처·법무 검토 문구
- 실제 운영 도메인·DNS·HTTPS·백엔드 서버·DB 비밀값
- DB 백업·복구·접근 로그·장애 대응·상담 알림 연동 정책

GitHub Pages 배포 성공은 프론트엔드 정적 사이트의 배포를 의미합니다. 백엔드·DB 연결, 상담 저장, 관리자 데이터 변경이 GitHub Pages만으로 운영되는 것은 아닙니다.

## 7. 최종 판정

사이트의 핵심 페이지·콘텐츠·이미지·디자인·시연/운영 경계를 한 기준으로 정렬했습니다. 남은 외부 운영 정보는 사실을 임의로 채우지 않고 운영기관 확정 항목으로 분리했습니다.
