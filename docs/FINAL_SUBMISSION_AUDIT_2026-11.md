# IT ACADEMY 최종 제출 전 콘텐츠·기능 점검

**점검 기준:** 2026-11-10  
**대상:** `main` 기반 최종 제출 보강 브랜치  
**범위:** 공개 웹사이트 콘텐츠, 사용자 흐름, 반응형 구성, 접근성, 프로젝트 자료 연결, 자동화 테스트와 운영 경계

## 1. 최종 점검 요약

이번 점검은 화면에 장식 요소를 더하는 작업보다 방문자가 각 페이지에서 필요한 정보를 이해하고 다음 행동으로 이동할 수 있는지를 기준으로 진행했습니다.

| 영역 | 점검 결과 | 보강 내용 |
|---|---|---|
| 메인 | 학습 방법과 프로젝트 소개는 충분하나 결과물의 증거 구조 설명이 추가로 필요 | 요구사항부터 회고까지 포트폴리오에 남길 다섯 가지 근거 추가 |
| 교육 철학 | 원리 중심·프로젝트 중심·책임 있는 AI 활용·피드백 구조 확인 | 기존 원칙을 유지하고 실제 성과처럼 보일 수 있는 PASS·CHECKED 장식 제거 |
| 교육과정 목록 | 과정 카드만으로는 분야 선택 기준이 짧음 | AI·데이터·생성형 AI·웹의 문제 유형과 대표 학습 산출물 비교 가이드 추가 |
| 교육과정 상세 | 커리큘럼·프로젝트·평가·FAQ 구조 확인 | 기존 상세 콘텐츠 유지, 운영정보 확인 전 임의 일정·비용 비노출 유지 |
| 프로젝트 | 6개 예시의 문제·해결 접근·기술·산출물·평가 구조 확인 | 이미지와 콘텐츠 연결 유지, 예시 프로젝트라는 공개 원칙 강화 |
| 공지사항 | 정적 공개 화면에 10개 샘플 게시글 제공 | 운영 공지와 교육 설계용 샘플을 구분 |
| 상담 | 양식은 있으나 좌측 정보 밀도와 개인정보 입력 안내가 부족 | 상담 준비 4항목, 진행 3단계, 필수·선택 입력 정보 안내 추가 |
| 관리자 | 대시보드·과정·공지·상담·권한 관리의 기존 구조 확인 | 공개 화면과 관리자 API의 권한 경계를 유지 |
| 문서 | README·교육 설계·품질·발표 자료 연결 확인 | 최종 점검 문서 추가, 품질 문서의 문자 그대로 들어간 줄바꿈 수정 |

## 2. 화면별 콘텐츠 구성

### 메인 페이지

프로젝트 갤러리 소개 뒤에 포트폴리오 증거 구조를 추가했습니다.

1. 문제와 요구사항: 문제 정의서, 사용자 흐름, 요구사항 목록
2. 설계와 데이터: 화면 설계, ERD, API 명세
3. 구현과 변경: 저장소, 커밋 이력, 코드 리뷰
4. 테스트와 품질: 테스트 케이스, 실행 결과, 이슈 기록
5. 배포와 회고: README, 시연 자료, 회고 문서

이 항목은 제출을 권장하는 포트폴리오 구성 기준입니다. 실제로 준비되지 않은 테스트 결과나 수강생 성과가 완료된 것처럼 표시하지 않습니다.

히어로의 상태 배지 중 실제 실행 결과로 오인될 수 있는 `PASS`와 `CHECKED`를 제거하고, `TEST PLAN`과 `CODE REVIEW`의 필수 점검 항목으로 변경했습니다.

### 교육과정 목록

과정명만으로 분야를 선택하기 어려운 방문자를 위해 네 가지 선택 가이드를 추가했습니다.

| 분야 | 핵심 작업 | 대표 학습 산출물 |
|---|---|---|
| AI | 데이터 패턴 분석, 예측·추천 모델 비교 | 데이터 사전, 모델 비교표, 추천 서비스 시연 |
| DATA | 데이터 추출·정제, 지표 설계, 시각화 | 품질 점검표, SQL 분석, 대시보드 |
| GEN AI | LLM·임베딩·검색·근거 검증 | 문서 처리 흐름, 검색 평가, RAG 시연 |
| WEB | 화면·서버·DB·인증 통합 | 화면 설계, API 명세, 통합 웹 서비스 |

모집 일정, 정원, 비용과 지원 조건은 운영기관에서 확인한 정보만 공개한다는 기존 원칙을 유지합니다.

### 상담 신청

상담 전에 정리하면 좋은 항목을 추가했습니다.

관심 분야와 현재 학습 경험을 먼저 정리하도록 안내합니다. 학습 가능 시간과 목표 결과물도 함께 준비하도록 설명합니다.

상담 진행 흐름은 희망 과정 선택, 신청 정보 작성, 실제 서버 접수 확인의 세 단계로 표시합니다.

필수 입력 정보는 이름, 연락처, 희망 교육과정, 문의 내용입니다. 이메일과 상담 희망 일시, 마케팅 수신은 선택 정보로 표시합니다.

개인정보 처리 주체, 보유 기간, 파기 기준과 문의처는 제공되지 않았습니다. 해당 항목을 사실처럼 작성하지 않고 실제 접수 운영 전에 기관이 확정해 공지해야 한다는 점을 명시합니다.

### 프로젝트 및 공지사항

프로젝트 6개는 교육 설계 예시로 유지합니다. 실제 수강생 작품, 취업률, 수상 이력으로 표시하지 않습니다.

프로젝트마다 전용 SVG 이미지가 홈·갤러리·상세 모달에 연결되어 있는지 확인하는 자동 테스트를 추가했습니다.

공지 샘플 10개는 공개 화면 시연용 콘텐츠입니다. 실제 운영 공지로 사용하기 전에 운영기관의 승인된 일정과 정책으로 교체해야 합니다.

## 3. 반응형 및 접근성 기준

새로 추가한 과정 선택 카드와 상담 안내, 포트폴리오 증거 카드는 데스크톱·태블릿·모바일용 별도 그리드 규칙을 포함합니다.

키보드 포커스 표시와 기존의 reduced-motion 처리를 유지합니다. 새 애니메이션 카드에는 움직임 감소 설정을 반영합니다.

실제 기기에서의 시각 검수는 별도 절차입니다. 자동화 빌드 성공만으로 모든 해상도의 픽셀 단위 화면 검수가 끝났다고 판단하지 않습니다.

권장 수동 검수 해상도는 360px, 390px, 768px, 1024px, 1440px입니다.

## 4. 자동화 검증

프론트엔드 테스트는 기존 탐색·날짜·대비 테스트와 공지 콘텐츠 테스트에 더해 최종 페이지 콘텐츠 테스트를 포함합니다.

최종 콘텐츠 회귀 테스트는 다음을 확인합니다.

- 교육과정 목록의 네 가지 분야별 가이드와 산출물 설명 존재
- 상담 준비 항목, 진행 흐름, 필수·선택 입력 정보 안내 존재
- 메인 페이지의 포트폴리오 증거 구조 존재
- 실제 실행 결과처럼 오인할 수 있는 PASS·CHECKED 문구 미사용
- 프로젝트 이미지 6개 파일과 프로젝트별 연결 존재
- 최종 점검 문서의 README 연결 존재

GitHub Actions의 Build Check는 프론트엔드 빌드·단위 테스트, 백엔드 테스트·빌드, Docker Compose 구성과 이미지 빌드에 더해 Chromium 브라우저 회귀 테스트 6개를 실행합니다.

브라우저 테스트는 GitHub Pages의 `/ITEducation/` 경로를 그대로 재현합니다. 메인·과정 탐색과 상세, 샘플 공지 상세, 프로젝트 모달의 Escape 닫기와 포커스 복원, 백엔드 없는 상담 신청의 성공 오표시 방지, 404 화면, 360px 모바일 가로 넘침을 확인합니다.

실패 시 Playwright 스크린샷과 Trace를 GitHub Actions artifact로 7일간 보관합니다.

## 5. 실제 운영 전 필수 확정 사항

다음 항목은 저장소 안의 코드만으로 결정할 수 없습니다.

- 교육기관의 공식 명칭, 주소, 대표 연락처와 운영 주체
- 과정별 실제 교육 기간, 수업 방식, 개강일, 정원, 비용, 지원 자격
- 강사·멘토 이력 및 검증 가능한 교육 실적
- 개인정보 처리 주체, 수집·이용 목적, 보유·파기 기간, 문의처와 동의 문구
- 실제 운영 도메인, HTTPS, 백엔드 서버, DB 계정과 비밀키
- DB 백업·복구 주기, 접근 로그, 장애 대응 담당자
- 상담 접수 알림을 위한 이메일·문자 연동 및 스팸 방지 정책

GitHub Pages는 프론트엔드 정적 미리보기입니다. 실제 상담 신청과 관리자 데이터 변경은 백엔드와 DB가 연결된 환경에서만 저장됩니다.

## 6. 최종 판정

**콘텐츠 구조와 화면 정보 밀도는 최종 제출용으로 보강했습니다.** 교육과정 선택, 프로젝트 근거, 상담 준비라는 방문자의 주요 질문에 답하도록 내용을 연결했습니다.

**기관의 실제 운영 정보와 개인정보 정책은 확인 불가 상태입니다.** 해당 정보는 추정하거나 임의로 만들어 공개하지 않았습니다.

2026-11-10 기준 Chromium 브라우저 회귀 테스트 6개와 프론트엔드·백엔드·Docker 검증이 GitHub Actions에서 통과했습니다. 브라우저 실기기 QA는 자동화 테스트와 별도로 수행해야 합니다.
