# IT ACADEMY 공개 사이트 전체 재설계

- 기준일: 2026-11-10
- 대상: 공개 홈, 교육과정 목록/상세, 공지 목록/상세, 상담, 교육 철학/프로젝트 및 공유 내비게이션·푸터
- 구현 기준: React 18 + JavaScript + React.createElement, Vite, 기존 Spring API 계약 유지

## 목적과 방문자

방문자는 프로그래밍·AI 교육에 관심이 있는 예비 학습자와 보호자다. 첫 방문에서 다음 질문을 빠르게 해결해야 한다.

1. 어떤 분야의 교육을 다루는가?
2. 현재 경험과 목표에 어떤 과정이 맞는가?
3. 각 과정에서 무엇을 배우고 어떤 결과물을 설계하는가?
4. 운영 조건이 아직 공개되지 않았다면 무엇이 미확정인가?
5. 실제 상담을 신청할 수 있는 환경인가?

주요 행동은 과정 비교 후 상담 안내로 이동하는 것이다. 교육기관의 공식 일정·비용·정원·연락처·강사·수강생 성과는 사실 확인 자료가 없으므로 만들지 않는다.

## 현재 문제 확인

- 서로 다른 세대의 CSS(styles.css, academy.css, professional.css, experience.css, design-system.css)가 동시에 로드되어 같은 컴포넌트의 색·크기·배경을 반복해서 덮는다.
- 교육과정 페이지는 검색·필터 외에 중복된 경로 안내와 이전 카드/영문 라벨/placeholder 기간·모집 상태가 한 페이지에 섞여 있다.
- 프로젝트 100점 프레임워크는 실제 학원 운영의 평가 규정인지 확인되지 않았고 예비 학습자에게 과정 선택 정보를 주지 않는다.
- 정적 미리보기에 실제 공지처럼 보이는 10개 가상 게시물이 존재한다.
- 공지 태그가 한 색상 클래스를 공유하고, 목록 헤더·상세 본문·하단 탐색이 정보 계층을 충분히 표현하지 못한다.
- 정적 미리보기의 상담 화면은 실제 서버 저장이 불가능한데도 개인정보 입력 폼을 노출한다.
- 기존 파비콘은 어두운 그라데이션과 작은 IT 텍스트로 사이트 새 시각 언어와 일치하지 않는다.

## 선택한 방향

**학습 안내서(prospectus) / 기술 교육 필드 가이드**로 전면 재구성한다.

- 차가운 연회색 종이 바탕, 잉크색 본문, 딥 틸 브랜드 컬러, 제한된 청록/파랑/황색 상태 색을 사용한다.
- Korean-first Pretendard Variable 한 계열, 명확한 크기·굵기 체계, 읽기 편한 줄 길이와 1.5 이상의 행간을 사용한다.
- 페이지는 카드 더미가 아니라 큰 제목, 분명한 섹션 구조, 얇은 규칙선, 넓은 콘텐츠 열, 교육과정 표/목록으로 구성한다.
- 모든 라벨은 자연스러운 한국어 문장형으로 쓰고, 장식용 영문 대문자 eyebrow, 중복 점수 뱃지, 3D 큐브·그라데이션·모션 효과를 제거한다.
- 모바일은 한 열로 재배치하고, 탭·필터·폼 컨트롤은 손가락으로 누르기 쉬운 크기를 확보한다.

### 고려한 방법

1. 기존 레이아웃에 색상만 덧씌우기: 빠르지만 현재 불일치와 과도한 중복을 해결하지 못하므로 제외.
2. 전면 재구성 + 기존 API와 동작 보존: 방문자 흐름을 다시 설계하면서 기존 검색·필터·API·폼 계약을 유지하므로 선택.
3. 다른 프레임워크/컴포넌트 라이브러리로 이전: 이번 문제 해결에 필요하지 않고 회귀 위험만 키우므로 제외.

## 페이지 구조

### 홈
- 한 문장의 교육 약속과 두 개의 명확한 행동(교육과정 보기 / 상담 안내).
- 교육 분야 네 가지를 예비 학습자의 관심 분야와 학습 결과로 소개.
- 학습 순서(기초 이해 → 직접 실습 → 팀/개인 프로젝트 → 검증·문서화)와 예시 프로젝트 결과물을 설명.
- 공식 성과나 수강생 작품으로 오인될 자료 없이 교육 설계 사례만 안내.
- 100점 평가표와 내부 코드 리뷰 체크리스트는 홈 홍보 흐름에서 제거.

### 교육과정 목록
- 분야 선택과 검색이 페이지 첫 화면에서 명확히 보이도록 구성.
- 하나의 과정 카탈로그를 사용하며 과정마다 대상 적합성, 학습 목표, 핵심 기술, 대표 결과물을 비교.
- 확인되지 않은 기간·모집 상태를 모든 카드에 반복하지 않는다. 운영 조건은 별도 미확정 안내로 묶는다.
- 검색·분야 필터 결과, 로딩·오류·빈 결과를 각각 설계한다.

### 교육과정 상세
- 과정의 학습 목표와 핵심 결과를 먼저 보여준다.
- 단계별 커리큘럼에 학습 주제·직접 해볼 실습·남길 산출물을 명확히 표시.
- 최종 프로젝트, 필요한 준비, FAQ, 상담에서 확인할 운영 조건을 배치.
- 확인되지 않은 모집 일정·기간·교육비·정원·지원 자격을 사실처럼 표시하지 않는다.

### 공지
- 정적 GitHub Pages 미리보기의 가상 게시물을 없앤다. 게시물이 없으면 정확한 빈 상태와 교육과정·상담 링크를 제공한다.
- 실제 API 게시물이 있으면 공지 분류별 태그 색을 구분하고, 목록은 분류·제목·작성일 열을 분리한다.
- 상세는 날짜/분류/중요 공지를 제목 위에 정리하고 본문 줄바꿈·목록을 유지하며 실제 목록으로 돌아가는 링크를 제공한다.
- 기존 공지 API, 목록·상세 라우트, 검색·분류·페이지네이션을 보존한다.

### 상담
- 백엔드가 연결되지 않은 정적 미리보기에서는 개인정보 폼을 노출하지 않는다. 접수 저장이 불가능하다는 사실과 상담 준비 정보, 과정 탐색 링크만 제공한다.
- 실제 서비스 모드에서는 기존 입력 name, API payload, CSRF, 필수 동의, 서버 응답을 보존하며 폼 상태·오류·진행·접수 완료를 다시 설계한다.
- 실제 개인정보 처리방침이 확정되지 않은 문구를 임의로 만들지 않는다.

### 공유 요소 / 파비콘
- 전 페이지 헤더·푸터, 본문 폭, 폰트, 간격, 버튼, 링크, 태그, 입력·포커스 상태를 통일한다.
- 새 브랜드 마크는 작은 크기에서도 식별되는 단순한 선형 학습/열린 책 모티프를 사용하고, 기존 favicon URL을 유지한다.

## 보존해야 할 기능과 계약

- React Router URL과 페이지 접근성
- 교육과정 API /courses, 프로젝트 API /projects, 공지 API /notices, /notices/{id}, 상담 API /inquiries
- 검색 및 분야 필터, 공지 분류·검색·페이지네이션, 프로젝트 필터·상세 모달의 키보드 동작
- 상담 폼의 서버 검증, 개인정보 동의, 접수번호 표시, 오류 처리
- 관리자 라우트와 기존 CSS/기능은 공개 영역 재설계에 의해 손상되지 않아야 한다.
- name, id, type, href, route, API 필드·payload를 이유 없이 변경하지 않는다.

## 비목표

- 실제 모집 일정/비용/정원/주소·연락처·강사·실적을 발명하지 않는다.
- 백엔드 API나 DB 스키마를 변경하지 않는다.
- 관리자 화면 전체 개편, 새 프레임워크 도입, 가짜 공지/가상 성과 추가를 하지 않는다.

## 완료 조건

- 전체 공개 페이지에 같은 디자인 토큰과 타이포그래피가 적용되고 이전 CSS의 시각 잔재가 겉으로 드러나지 않는다.
- 교육과정 목록/상세, 공지 목록/상세, 상담의 내용·동작이 위 구조를 따른다.
- 가상 공지와 가짜 평가 점수표가 공개 페이지에서 제거된다.
- favicon이 새 브랜드 마크로 바뀐다.
- 프론트엔드 빌드·단위 테스트·백엔드 회귀 테스트·Chromium 브라우저 테스트가 통과한다.
- 360, 390, 768, 1024, 1440px에서 가로 넘침이 없고 주요 화면의 스크린샷을 직접 검토한다.
- PR 병합 후 Pages 배포 성공과 공개 배포 artifact 커밋을 확인한 뒤에만 완료로 보고한다.
